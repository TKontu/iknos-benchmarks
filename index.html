Local AI models on the Iknos evidence-reasoning tasks

Iknos is an evidence-reasoning engine. We tested six AI language models, running on our own GPUs, on the five language tasks Iknos depends on, using the exact instructions Iknos gives them in production. The test questions, the pass marks and the rule for picking a winner were all fixed and published before any candidate was tested.

How to read this page
  • Score — the share of test items a model got right (for R4, the share it got wrong — lower is better).
  • Safe-side figure (the number with ↑ or ↓) — a test of a few hundred items has a margin of error, so a model is judged on the cautious end of that margin, not its raw score. That way a lucky run can't pass. (Statisticians: the Wilson 95% interval bound.)
  • Pass mark — the safe-side figure must clear it; ✓ passes, ✗ fails.
  • Screen and confirmation sets — two separate sets of test items. A model is first tried on the screen set; only models still in contention go on to the confirmation set, which nobody had looked at. Models that clearly failed were stopped after the screen.
  • Compression formats (AWQ, FP8, Q4_K_XL, bf16 = uncompressed) — ways of shrinking a model so it fits on one graphics card; vLLM and llama.cpp are the programs that run it.

Tasks and pass marks

TaskWhat is measuredPass mark
R1 Negation rewriteRewrites a "not X" statement in positive form without changing its meaning≥ 90% right, safe-side ≥ 85%
R2 Entity extractionFinds the things (parts, people, places…) a text namessafe-side ≥ 85% found; invents ≤ 2%; finds things in text that has none ≤ 5%
R3 VerifierCatches a claim that was subtly altered from its sourcesafe-side ≥ 90% caught; wrongly rejects correct claims ≤ 10%
R4 Claim extractionClaims pulled from a text that the text doesn't actually support (lower is better)safe-side ≤ 10%; passages it fails to process ≤ 10%
R5 Evidence judgeDecides whether a piece of evidence supports or contradicts an explanationsafe-side ≥ 80% right; calls contradicting evidence "supporting" ≤ 10%

Winner: among models passing every task, the best safe-side R5 score; if none passes everything, the best safe-side R5 score, with its failures listed.

How the test was kept fair

The test items were fixed and fingerprinted (codes below) before any candidate ran, and nobody looked at the confirmation items in advance. A few protocol changes (amendments 11–15) were made after the current model's first run, before any candidate ran. For R5, the correct answers are cases where three different models agreed, each then checked by an independent reviewer against written rules. The source documents are private, so only totals are published.
